# Intern Training System - Decision Log

- **Decision 1:** The system serves both current interns AND future batches — one path that fixes today's team and becomes the reusable onboarding bootcamp for every future hire.
- **Decision 2:** The core outcome is the AI-first habit, not topic knowledge: interns go to AI first (as friend, guide, developer, tester), grill a requirement and understand use cases before coding, and build at AI-era speed without fearing AI. The captain stops being first responder and repeating teacher.
- **Decision 3:** Users are mixed coding-background interns — the site has sections per language (HTML/CSS, JS, React, Python) so each intern takes what they lack. Language basics stay thin (as in the SOPs); the real curriculum is AI + CLI + engineering judgment for internal projects: UI why (sidebar, tabs vs tables), server-side vs frontend processing, API design (one API vs many), unit testing, clean code. Current weak point to fix first: FRONTEND.
- **Decision 4:** THE outcome = the full journey alone: intern gets an internal project → grills it, plans it, builds it with Claude Code (full stack: React, HTML/CSS/JS, Python) → captain only sees the demo. Graduation gate = a capstone with zero company use (e.g., a School CRM) that exists purely to teach the "why": minimal UI, one click beats two clicks, every element justified — the bridge before real internal projects.
- **Decision 5:** v1 is a guided CONTENT website — no login, no accounts, no dashboard, no LMS features, no task delivery via Claude Code. One ordered path: every page tells the intern exactly what to do next (learn this → watch this video → build this). Interns freely skip what they already know — no forcing, no profile, no gate. Party-popper celebration when one module is completed and they move to the next. Progress lives in the browser only.
- **Decision 6:** v1 ships with EVERYTHING: all twelve modules — HTML/CSS, JavaScript, React, Python/Flask, Database, CLI, Git, Agent Coding (context, rules, skills, screenshots), API Design, Frontend UI Design, Clean Code & Testing, and the School CRM capstone — EN + Hinglish on every page from day one.
- **Decision 7:** Postponed: captain dashboard, certificates, embedded AI chat, logins. Quizzes / auto-grading ARE allowed in v1 but only as pure frontend (self-checked, no server). The site itself is 100% frontend, no backend — static build, browser-only progress.
- **Decision 8:** The sidebar is the walk order, one module after another: 1) HTML/CSS, 2) JavaScript, 3) React, 4) Python/Flask, 5) Database, 6) CLI (terminal), 7) Git, 8) Agent Coding, 9) API Design, 10) Frontend UI Design, 11) Clean Code & Testing, 12) School CRM capstone. Language projects use plain AI chat, per the existing SOPs; the capstone is built fully with agent coding. The learning-approach mindset (ask why, root cause, plan before code, one small change at a time, you supervise AI) lives on the home page and inside each module's Start Here page — not as its own section.
- **Decision 9:** Architecture (FIRSTMATE's call, captain accepted): content as Markdown files — one file per topic page, editable directly (swap video links, fix Hinglish, no code, no rebuild) — rendered by a small static site that runs as a proper website on any static hosting. Explicitly rejected: single HTML file, JSON content. localStorage for check-offs + party popper + frontend-only self-check quizzes. No API, no database, no auth, no server.
- **Decision 10:** The four missing modules (CLI, Claude Code, UI-why, School CRM capstone) are written fully by AI from the existing SOPs, rules files, and learning approach — the captain only reviews and approves page by page. Decision 6 scope unchanged: v1 still ships everything.
- **Decision 11:** The static site is VitePress — markdown-native content, built-in linear next/prev flow, custom components for party popper and check-offs, plain static build. Rejected: Astro, Docusaurus, hand-built renderer, React SPA, plain HTML + Tailwind.
- **Decision 12:** Every concept page carries 1–2 YouTube video links provided by the captain — AI never chooses videos. English and Hinglish pages may carry different videos. Links live in the markdown as one-line edits, and pages ship with empty, clearly marked video slots until the captain pastes them. No captain recording, no AI-generated video in v1.
- **Decision 13:** Site top bar carries two site-wide toggles (captain's call): English / Hindi language switch — both versions exist per D6, shown one at a time, never stacked — and light / dark mode (free with VitePress). Content on the Hindi side stays Hinglish (Roman script) per D6.
- **Decision 14:** The built site lives on Netlify's free tier, unlisted URL, deploying automatically on every push — captain's call over company-server hosting. The site name is unguessable, chosen by the captain alone at deploy time; until then the top bar shows the placeholder title "Intern Training".
- **Decision 15:** Language topics are grouped into cluster pages — for example JavaScript has "Conditions & Loops" as one page. Not one page per topic, not one long page per language. Each page is one sitting.
- **Decision 16:** Every module's last page ends with a Test Yourself section — about five questions, answers shown on click. Self-check only: no gating, no saved score.
- **Decision 17:** Git is its own module, and the CLI module covers terminal only. CLI pages: GUI vs terminal, essential commands hands-on, running things — the goal is removing the fear of the terminal. Git pages: what git actually is, the working tree → staging → commits flow with status/add/commit/log, remote basics (clone, push, pull), branches at a glance.
- **Decision 18:** A Database module sits right after Python/Flask: SQLite locally (tables, SQL CRUD), SQLite with Python from Flask, Postgres and server databases with connecting to a server, MongoDB basics, and choosing between them.
- **Decision 19:** The Python/Flask module includes how to run Python and Flask and serve the app on a server, not just localhost. Client-side vs server-side is explained in basic words on the HTML/CSS Start Here page and again on the Python Start Here page.
- **Decision 20:** The Claude Code module is named Agent Coding. Claude Code is the main tool shown; Gemini CLI is mentioned as the alternative. The closing message: tools will change, the principles stay the same.
- **Decision 21:** A Clean Code & Testing module sits after Frontend UI Design and before the capstone: why clean code matters, naming and functions and guard clauses, DRY and data flow, SOLID in plain words, and why testing exists with a few unit tests written hands-on.
- **Decision 22:** Every page follows one skeleton: short concept in English and Hinglish → one or two video links → hands-on → check-off. The home page shows the journey with progress dots, how to use this site, and a Continue button to the last unfinished page.
- **Decision 23:** The captain supplies the real Claude Code screenshots for the Agent Coding module. Pages carry marked placeholder slots until the screenshots are dropped in during review.
- **Decision 24:** No analytics in v1. The site stays a pure static build with zero tracking.
- **Decision 25:** The site code lives in a `site/` subfolder of this project. Git is initialized at the project root, and the code is pushed to a private GitHub repo. Creating the GitHub repo is the captain's manual step.
- **Decision 26:** English is the default locale on first visit; Hinglish is one click away in the top bar.
- **Decision 27:** Build order is pilot-first: full shell (top bar with both toggles, sidebar listing all twelve modules, check-off, quiz, party popper) + home page + all 8 HTML/CSS pages in English and Hinglish, video slots empty. The captain reviews the look and says good / change this — only then the remaining eleven modules are built.
- **Decision 28:** VitePress built-in local search is ON — fully client-side, no backend, respects the static-only rule.
